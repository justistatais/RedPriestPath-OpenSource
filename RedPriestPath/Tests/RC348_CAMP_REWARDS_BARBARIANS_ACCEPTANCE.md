# rc.348／资源380营地封印物与普通蛮族复验

本清单用于游戏内验收。Lua替身、数据库、构建和哈希通过不等于单机或多人已通过。

1. 完全退出游戏后重新启动，日志应出现 `resource=380 diagnostics=off`；分别测试普通单机和一个真人创建的多人房间。救赎模式开启时才适用清理普通蛮族的规则。
2. 读取此前仍有普通蛮族的救赎存档。首次修复应出现 `rescue cleanup version=2 ... complete=true`，确认无失控者标识的残留消失，真正失控者、旧中心守卫和终局单位保留。成功后后续回合不应重复全量迁移。
3. 继续数个世界回合，检查引擎新生成的普通蛮族是否在下一个同步结算后清除；模组自己补建的营地检查 `normalRemoved`。记录仍存活单位的地点、生成与观察回合，不能只凭勇士／投石兵模型判定其身份。
4. 清除工坊营地后，单机沿用即时结算；多人房间沿用两段同步队列，查看 `network removal observed`、`network settlement queued` 和 `network cleared` 的回合。此次旧日志玩家0在回合6清除plot3885，回合7排队，应继续到回合8检查封印物账本及通知。
5. 读取已有待发奖励的存档，确认只发一次；重复回调不重复发奖。`improvementOwner=63` 仅是营地原主人，不能据此认定清营者或补发。
6. 两个真实客户端、重载、驱散氏族和海岸扫荡分别验证归属。现行最后入格者／同步边界占格回退仍存在因果识别边界，本轮保留原奖励覆盖，只补时序日志，不宣称所有漏奖场景已解决。

若仍异常，保留同一局的 Lua.log、net_message_debug.log、GameCore.log 与实际回合数。不要覆盖原始证据。
