# 拯救模式人工测试清单

以下检查必须在《文明 VI：风云变幻》游戏内执行。静态测试不能替代这些检查。
每组关键场景都应保存、退出并重新载入一次；联机候选检查需要两个真实客户端。
下面“资源291必测”只收录本轮修复；更早清单作为历史回归索引。

## 资源291必测：本地事件权威、神器排序与终局战斗

1. [ ] 双方完全退出文明VI后安装同一资源291 ZIP并核对SHA-256；新救援局两端必须出现bundle 33模块校验、SyncActions v7、Phase7 v5、Artifacts v4、Phase10A v4和Phase10 v38，不得出现Lua Runtime Error／FATAL。
2. [ ] 先回归双方途径可选、中央76格视野、四座封印城和28组永久联盟，再连续进行到至少世界回合12；第1～12回合每次同步检查均应为0差异，不得再出现相邻`DynamicModifier`编号循环错位、自动快照恢复或开局链缺失。
3. [ ] 在同一世界回合并发触发科技／市政完成、项目完成、城市易主、贸易路线、完美者尤里卡／鼓舞／建造者改良／科学家招募、神器获得与AI单位生成。事件回调所在回合不得直接创建同步Modifier；下一完整世界回合的稳定锚点按QueuedTurn、PlayerID及对象ID结算，完美者科学家必须先于项目且每项只记一次。
4. [ ] 在至少一个本地事实被捕获后、下一稳定锚点消费前保存并让一端掉线，再由原槽位重连继续两回合。必须确认引擎是否重放该事件，所有未结算事实不得丢失或重复；若失败，资源291不能宣称保存／重连安全，必须保留日志与存档继续修复。
5. [ ] 触发救援神器全局重算，包含多名主要文明和多支单位；两端Ability／Modifier集合及创建顺序一致。同步外交状态变化只在同步锚点结算，本地外交回调不得直接写权威状态。
6. [ ] 终局分别验证：神对普通单位的饱和必杀、普通单位攻击神时遭神反击的饱和必杀、Boss非饱和受伤、第一条命死亡／复活、第二条命死亡／胜利。两端Boss epoch、伤害、复活次数和胜利完全一致；无可靠checkpoint或未观察到原生伤害增量时必须保守跳过补差，不得过量补伤。
7. [ ] 完成三教会各6使者项目后，在下一稳定锚点前让原城市易主或被摧毁；Phase10A仍应认定已发生的项目事实并生成玩家真神，但错误玩家、错误项目或不足使者不得通过。
8. [ ] 分别由两台电脑担任主机重复第2～6项中的关键场景并保存退出／重连；普通模式和单机对照保持既有即时行为，救援专属Property、Ability和单位不得污染普通模式。
9. [ ] 在同一世界回合制造一个蛮族UnitID被移除并复用的场景，明确覆盖Add→Remove、Remove→Add、Add→Remove→Add及可观察的其余全排列，并保留两端事件发布顺序日志；该`turn:owner:unitID`整批必须统一removal-wins，不得一端给新单位写工坊来源／强化而另一端丢弃。下一回合generation计数与持久unit队列一致。
10. [ ] 清除工坊后在同一PlotIndex立即重建营地，并让旧代和新代都产生单位；旧pending清营、教会／Phase4／神器奖励先恰好结算一次，随后camp epoch递增。旧单位不得增加新营计数、生成新营extra／monster或继承新营奖励状态。
11. [ ] 让一只旧营地魔物活过同格营地重建再死亡；其释放不得清除新营魔物slot或把旧冷却写入新营。另从共同未分叉资源290存档载入一只无`SOURCE_CAMP_EPOCH`旧魔物：只有原slot仍匹配该serial时才允许写回，slot不匹配必须fail-closed。
12. [ ] 用教会／外神的scripted kill分别击杀游走魔物和中心失控者，随后复用相同UnitID；日志与Property必须显示`TARGET_KIND/TARGET_SERIAL`匹配旧目标后清理，旧击杀者不得奖励、净化或结算到新代目标。魔物本地移除后先等待一次缺失确认，第二个稳定锚点才提交`LIVE=0`与active-index移除。
