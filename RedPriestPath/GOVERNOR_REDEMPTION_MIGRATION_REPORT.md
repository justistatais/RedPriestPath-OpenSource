# 总督普通模式至救赎模式迁移｜rc.401 / 资源433

本次按20261007任务书接入救赎模式三位总督。正义/魔术师技能实现复用普通模式；普通星星保持审讯报告、隐秘联络、隐秘守护。救赎星星使用独立 CASE_FILES、RED_GLOVES、HIDDEN_WORLD 晋升，不替换普通文本或普通技能设计。

## 实现与复用

共享总督数据库、图标、文本和UI在风云变幻下加载；救赎SQL/文本覆盖、终极晋升UI和新Gameplay模块同时有Criteria与运行时门控。救赎删除旧星星C/D的晋升树关系/Modifier绑定并关闭正常C5/D3租约；B2保留本城-2。正义/魔术师SQL不改数值，普通周期注册仍保留原路线，救赎周期使用同步PlayerTurnStarted。

- 案件档案：只接受同步战斗事件，己方单位或能从原生区划身份核实的城防击杀；受害者必须为敌方战斗单位，死亡地块必须归己方所有，水域按相同所有权规则处理。同步击杀钩子保存死亡位置/所有权与身份；对象已消失时必须有原生致死凭据，不能把脚本删除或转属当作击杀。奖励使用既有同步Random助手，持久身份键跨两种事件去重，每次只给300科技或300文化，无回合上限。
- 红手套巡查：一个玩家原生Movement Modifier，由资源租约启停；用原生PromotionClass及动态特殊单位排除条件分类，没有写死普通侦察/升级列表，也不补满已花费移动。每个单位独立保存巡查七格引用。移动完成命令检查原生当前位置、同步移动序号、身份、回合及技能生效代次；刷新只撤销本单位旧引用。下一己方同步回合清理；死亡、升级、换所有者、中和和离任清理。
- 隐秘世界：D同时要求C3和C4；原版总督界面副本仅新增此晋升的AND选择/确认检查，其他总督保持原代码。有效时全图逐格加一引用，失效逐格减同一份；只在启停边界与必要的加载恢复检查遍历，不逐帧/逐回合无条件重复加视野。探索知识不回退，普通六格A1单独维护，D撤销后仍按当前驻城有效状态保留。
- 读档：STAR_STATE_VERSION=1、UNIT_LEDGER_VERSION=1；单位元数据只首次接入全量初始化，后续按事件增量。已有 native visibility count 与持久引用账本均保留；加载时只补低于账本引用下限的计数，不无条件再加。已决击杀不会重抽奖或重发。当前已发布救赎没有旧三位总督技能，故不做推测头衔映射。
- 文本：六个救赎名称/说明及B2覆盖由独立Selected生成器生成；默认中文、模组英文选项再覆盖，不进入共享Selected文本包。普通星星文本保持。

专项Lua/数据库测试验证规则和状态机；原版UI副本做语法及分支检查。发布程序、SQL、包清单、哈希和救赎125文件保护检查结果记在本报告后续发布记录。所有旧证据和失败尝试保留。

## 待原生核对的边界

1. 原版高TransitionStrength的魔术师立即就职、训练与购买/升级覆盖、免费晋升与原生已有免费晋升叠加，及巨作基础文化/旅游仍沿用原实现的实机验收边界。
2. 同步 UnitKilledInCombat 若未在引擎发出，而受害者已从UnitManager消失，当前宁可记录“absent fatal proof”而不误奖。需真实击杀日志验证正常单位、救赎敌军和城防归因。重连/双端随机流也待实测。
3. 巡查依赖原版移动完成发布后拥有者UI提交同步命令；命令回执、跨端落点、升级/死亡时序与最大移动租约是否会影响已花费移动，必须原生核对。
4. 总督原生读数在UI，非活动玩家回合的EXECUTE_SCRIPT接收及中和撤销时机待验。Gameplay同步入口总会重新核对城市归属，UI不授予视野或收益。
5. ChangeVisibilityCount没有公开的来源句柄。持久账本可以成对管理本技能引用，但在引擎若仅重建部分计数、且其他原生视野恰好掩盖缺失引用时，正数本身不能证明来源归属。混合来源保存/掉线重连是必须核对的原生边界，不能用当前替身宣称计数绝不泄漏。
6. 旧档历史只能补录当前仍存在的已完成类型，不能恢复曾丢失/拆除且无旧记录的建筑；不伪造过去历史。剧情安排继续原有单目标FinishProgress方案，其合法生产队列与救赎资格项目的组合需手测。
